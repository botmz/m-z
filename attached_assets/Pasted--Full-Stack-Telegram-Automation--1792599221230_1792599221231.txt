أنت مهندس برمجيات Full-Stack خبير في بناء أنظمة Telegram Automation، وواجهات الإدارة العربية، والخدمات الخلفية التي تعمل باستمرار. أريد منك بناء مشروع ويب متكامل وحقيقي باسم MZ Telegram Bots، وليس مجرد تصميم واجهة أو نموذج تجريبي.

الهدف:
إنشاء منصة عربية لإدارة بوت تيليجرام يقوم بجلب رسائل التوصيات والتحليلات من قنوات تيليجرام العامة التي أحددها يدوياً، ثم إعادة نشرها في قنوات تيليجرام الخاصة بي التي أحددها، مع التحكم الكامل في كل مصدر ووجهة والترجمة وإضافة الروابط وأسعار الذهب والبيتكوين.

1. اللغة والتصميم:
- واجهة عربية بالكامل واتجاه RTL في جميع الصفحات والجداول والنماذج.
- تصميم احترافي فاخر بهوية MZ، يجمع الأسود والذهبي مع لمسات خضراء وحمراء للمؤشرات المالية.
- دعم الوضع الليلي والنهاري مع زر تبديل وحفظ الاختيار.
- تصميم Responsive متوافق مع الهاتف والتابلت والكمبيوتر.
- خطوط عربية واضحة مثل Cairo أو Tajawal، ورسوم بيانية وبطاقات إحصائية عند الحاجة.
- لا تضع بيانات تجريبية توحي بأنها حقيقية. اعرض حالات الاتصال الفعلية وأخطاء واضحة عند تعذر الاتصال.

2. تسجيل الدخول والحماية:
- صفحة دخول واحدة للوحة التحكم باستخدام كلمة مرور يحددها مالك المشروع عند أول تشغيل من خلال إعداد آمن.
- لا تضف تسجيل حسابات أو تسجيل دخول بالبريد الإلكتروني أو تسجيل اجتماعي أو استعادة كلمة مرور عبر البريد.
- تخزين كلمة المرور باستخدام Argon2 أو bcrypt، مع جلسات آمنة وCookies من نوع HttpOnly وSecure عند استخدام HTTPS وSameSite.
- حماية المسارات الإدارية في الخادم، وليس الواجهة فقط.
- تقييد محاولات الدخول، وتطبيق Rate Limiting، وانتهاء صلاحية الجلسة، وإمكانية تسجيل الخروج.
- لا تخزن كلمات مرور تيليجرام أو مفاتيح API أو كلمات مرور لوحة التحكم كنص مكشوف في قاعدة البيانات أو المستودع.
- استخدام متغيرات البيئة Secrets لتخزين BOT_TOKEN وAPI_ID وAPI_HASH ومفاتيح الخدمات وكلمة المرور الأولية.
- توفير آلية آمنة لتغيير كلمة مرور لوحة التحكم من داخلها بعد تسجيل الدخول.
- عدم عرض أي أسرار في سجلات النظام أو رسائل الأخطاء.

3. لوحة التحكم الرئيسية:
أنشئ Dashboard احترافية تعرض:
- حالة البوت: يعمل، متوقف، أو يوجد خطأ.
- حالة اتصال Telegram.
- عدد قنوات المصدر والقنوات المستقبلة النشطة.
- عدد الرسائل التي تمت معالجتها وإرسالها اليوم.
- عدد الرسائل الفاشلة والمعلقة.
- آخر الرسائل المنقولة مع وقت التنفيذ والمصدر والوجهة وحالة الإرسال.
- أزرار تشغيل النظام وإيقافه مؤقتاً وإعادة تشغيل عامل المعالجة.
- سجل أحداث وأخطاء مع إمكانية البحث والتصفية.
- زر لاختبار اتصال البوت وإرسال رسالة اختبار إلى قناة أختارها.
- لا تعرض حالة التشغيل على أنها ناجحة إلا بعد التأكد من حالة الخدمة فعلياً.

4. إدارة قنوات المصدر:
أنشئ صفحة كاملة لإدارة قنوات المصدر، مع إمكان:
- إضافة قناة جديدة باستخدام رابطها العام أو معرفها @channelname.
- تعديل بيانات القناة أو حذفها أو تعطيلها مؤقتاً دون حذف بقية الإعدادات.
- إضافة عدد متعدد من القنوات دون حد مصطنع داخل التطبيق.
- زر مستقل لكل قناة لتفعيل أو تعطيل استقبال الرسائل منها.
- خيار مستقل لكل قناة: ترجمة الرسائل إلى العربية أو إبقاؤها بلغتها الأصلية.
- إمكانية اختيار لغة الترجمة المستهدفة مستقبلاً، مع العربية كلغة افتراضية.
- خيار مستقل لإضافة رابط المصدر مع كل رسالة معاد نشرها.
- حقل لإضافة نص ثابت اختياري في بداية الرسالة أو نهايتها.
- خيار لتصفية أنواع الرسائل، مثل التوصيات فقط أو جميع الرسائل النصية أو النصوص مع الصور.
- إعداد طريقة التعامل مع الصور والتعليقات التوضيحية والتنسيقات والروابط.
- عرض آخر رسالة استقبلتها القناة وحالة آخر معالجة.
- إمكانية اختبار إعدادات القناة قبل تفعيلها.
- تأكيد قبل الحذف وإمكانية تعطيل القناة بدلاً من حذفها.
- لا تفترض أن القناة متاحة للقراءة لمجرد أنها عامة؛ تحقق من الإمكانية الفعلية.

5. إدارة القنوات المستقبلة:
أنشئ صفحة مستقلة لإدارة قنوات النشر التي يملكها المستخدم:
- إضافة قناة مستقبلة باستخدام معرفها أو رابطها.
- تعيين اسم وصفي لكل قناة.
- إضافة عدد متعدد من القنوات المستقبلة.
- تفعيل أو تعطيل كل قناة بصورة مستقلة.
- اختبار صلاحية الإرسال لكل قناة.
- عرض حالة صلاحيات البوت، مع إرشاد المستخدم إلى إضافة البوت ومنحه صلاحية النشر اللازمة.
- اختيار مصادر محددة لإرسال رسائلها إلى كل وجهة.
- إمكانية ربط مصدر واحد بعدة قنوات مستقبلة وربط عدة مصادر بوجهة واحدة.
- إعدادات مستقلة لكل وجهة، بما في ذلك شريط أسعار السوق وخيارات التنسيق.
- سجل بالرسائل المنشورة والأخطاء الخاصة بكل وجهة.
- زر إرسال رسالة اختبار بعد تأكيد المستخدم.

6. محرك نقل الرسائل:
- استخدم Telegram Bot API للنشر في القنوات التي يملك المستخدم صلاحية النشر فيها.
- استخدم Telegram MTProto عبر مكتبة موثوقة مثل Telethon أو Pyrogram أو بديل مدعوم للوصول إلى الرسائل من المصادر العامة، إذا كان ذلك مسموحاً وفق شروط تيليجرام وإعدادات الحساب.
- وضح أن Bot API وحده لا يتيح للبوت قراءة جميع رسائل القنوات العامة تلقائياً؛ يجب استخدام طريقة وصول مناسبة وصلاحيات صحيحة.
- لا تطلب من المستخدم مشاركة كلمة مرور حسابه الشخصي في لوحة التحكم.
- اجعل استقبال الرسائل مستمراً، وليس عبر فحص متقطع قصير أو سكربت يعمل فقط عند فتح المتصفح.
- استخدم Queue لمعالجة الرسائل، وإعادة المحاولة بتأخير تصاعدي عند الأخطاء المؤقتة، مع احترام حدود Telegram API.
- امنع التكرار باستخدام معرف المصدر ومعرف الرسالة، مع تسجيل كل محاولة إرسال.
- تعامل مع FloodWait وانقطاع الاتصال وأخطاء الصلاحيات.
- احفظ حالة الرسالة لمنع تكرارها بعد إعادة تشغيل الخدمة.
- دعم النصوص والصور والتعليقات التوضيحية والروابط، وحافظ قدر الإمكان على التنسيق الأصلي.
- سجل الأخطاء الحقيقية مع وقتها دون تسجيل الرموز السرية.
- أضف إمكانية إعادة محاولة الرسائل الفاشلة يدوياً.
- اجعل النظام قابلاً للتوسع دون إرسال الرسالة نفسها مرتين عند تعدد العمال.

7. ترجمة مستقلة لكل قناة مصدر:
- أضف مفتاح تشغيل/إيقاف باسم «ترجمة الرسائل إلى العربية» داخل إعدادات كل قناة مصدر.
- عندما تكون الترجمة مفعلة، ترجم نص الرسالة والتعليق التوضيحي للصورة إلى العربية، مع الحفاظ على الأرقام والأسعار والرموز المالية وأسماء الأصول والروابط ومعرفات التداول.
- عندما تكون الترجمة معطلة، انشر الرسالة بلغتها الأصلية دون تعديل لغوي.
- لا تترجم عناوين URL أو معرفات القنوات أو رموز التداول مثل BTC وXAUUSD.
- استخدم مزود ترجمة قابل للتبديل، مع توضيح إعداد مفتاح API والتكلفة المحتملة.
- عند فشل الترجمة، استخدم خياراً يحدده المستخدم: نشر النص الأصلي أو تعليق الرسالة وإظهار الخطأ.
- لا تجعل إعداد ترجمة مصدر واحد يؤثر على المصادر الأخرى.
- سجل حالة الترجمة لكل رسالة.

8. إضافة رابط قناة المصدر:
- أضف خياراً مستقلاً لكل مصدر بعنوان «إرفاق رابط المصدر».
- عند التفعيل، أضف في نهاية الرسالة رابطاً واضحاً مثل: «المصدر: اسم القناة».
- استخدم الرابط العام الصحيح للقناة أو رابط الرسالة الأصلية إذا كان متاحاً.
- لا تنشئ روابط غير صحيحة، ولا تدّع إمكانية الوصول إلى رسائل خاصة.
- حافظ على روابط المحتوى الأصلية الموجودة داخل الرسالة.
- تجنب تكرار رابط المصدر إذا كان مضافاً بالفعل.
- عند تعطيل الخيار، لا تضف أي رابط مصدر تلقائي إضافي.

9. شريط أسعار الذهب والبيتكوين:
أريد شريط أسعار سوقي يظهر أعلى المنشورات في كل قناة مستقبلة، وليس فقط داخل لوحة التحكم.
يجب أن يكون لكل قناة مستقبلة مفتاح تشغيل/إيقاف مستقل للشريط.

صيغة مقترحة للشريط:
🟡 الذهب XAU/USD: 4,250.00 $ ▲
₿ البيتكوين BTC/USD: 108,500.00 $ ▼

هذه الأرقام أمثلة توضيحية فقط وليست أسعاراً فعلية. لا تستخدمها كبيانات حية.

المتطلبات:
- جلب سعر الذهب الفوري XAU/USD وسعر البيتكوين BTC/USD من مزود أسعار موثوق.
- استخدام API موثق، مع بيان المصدر ووقت آخر تحديث.
- استخدم السهم الأخضر ▲ عندما يكون السعر أعلى من السعر المرجعي السابق المحدد، والسهم الأحمر ▼ عندما يكون أقل منه.
- استخدم مؤشراً محايداً عندما لا يتغير السعر أو عندما لا تتوفر بيانات كافية، ولا تختلق اتجاه السعر.
- وضح معيار المقارنة: التغير منذ آخر قراءة ناجحة أو التغير خلال فترة محددة يختارها المستخدم.
- احفظ السعر السابق الصحيح في قاعدة البيانات حتى لا يتغير الاتجاه بشكل عشوائي عند إعادة تشغيل الخدمة.
- أضف وقت تحديث الأسعار وإمكانية ضبط الفاصل الزمني مع احترام حدود API.
- عند تعذر جلب الأسعار، اعرض آخر سعر مع وقت تحديثه أو أخفِ السعر حسب الإعداد؛ لا تعرض قيمة قديمة على أنها حديثة.
- أضف إعدادات مستقلة لكل قناة مستقبلة: إظهار الذهب، إظهار البيتكوين، ترتيب العملات، وتنسيق الشريط.
- أضف الشريط قبل محتوى الرسالة المعاد نشرها، وليس في رسالة منفصلة افتراضياً.
- انتبه إلى حدود طول الرسالة في Telegram، وإلى تنسيق HTML أو Markdown عند إدراج الشريط.
- لا تضف الشريط إلى الرسائل القديمة عند تعديل الأسعار إلا إذا فعّل المستخدم خياراً صريحاً لذلك.
- لا تعد بنشر أسعار متجددة تلقائياً في أعلى القناة من دون رسائل جديدة. وضح أن تعديل الشريط على المنشورات السابقة أو نشر تحديث مستقل ميزة منفصلة تحتاج إلى إعداد.

10. قواعد ربط المصدر بالوجهة:
- أنشئ واجهة مرئية لاختيار أي مصدر يرسل إلى أي وجهة.
- أتح لكل مصدر تحديد وجهة واحدة أو أكثر.
- أتح لكل وجهة تحديد المصادر المسموح بها.
- تحقق من الإعدادات المتعارضة وأظهر رسائل واضحة.
- لا تنشر الرسائل من مصدر معطل أو إلى وجهة معطلة.
- أضف وضع معاينة يوضح شكل الرسالة النهائي قبل الإرسال، شاملاً الترجمة ورابط المصدر وشريط الأسعار.

11. قاعدة البيانات:
استخدم PostgreSQL للإنتاج، مع مخطط منظم لجداول:
users أو admin_settings لمالك لوحة التحكم الوحيد، source_channels، destination_channels، routing_rules، messages، message_deliveries، market_prices، app_settings، audit_logs.
لا تنشئ نظام تسجيل عام للمستخدمين.
خزّن إعدادات كل قناة على حدة.
أنشئ ترحيلات قاعدة بيانات موثوقة، وفهارس مناسبة، وقيوداً لمنع التكرار.
وفر نسخاً احتياطية وإرشادات استعادة.
لا تحفظ Session تيليجرام في المستودع أو الواجهة الأمامية؛ خزّنها بصورة مشفرة وآمنة في الخادم.

12. التقنية المقترحة:
- Frontend: React أو Next.js مع TypeScript.
- تصميم: Tailwind CSS مع مكونات احترافية ودعم RTL.
- Backend: Python مع FastAPI أو Node.js مع TypeScript، واختر بنية متوافقة مع مكتبة تيليجرام المستخدمة.
- Telegram: Bot API للنشر وMTProto للقراءة عندما يكون ذلك ضرورياً ومسموحاً.
- Database: PostgreSQL.
- Queue: Redis مع عامل معالجة دائم عند الحاجة.
- Market data: مزود API لأسعار الذهب والبيتكوين.
- Translation: مزود ترجمة قابل للتهيئة.
- افصل الواجهة الأمامية عن عامل تيليجرام وخدمة الأسعار.
- استخدم إصدارات مستقرة ومدعومة من المكتبات.

13. التشغيل على مدار 24/7:
- شغّل المعالجة في خدمة Backend دائمة مستقلة عن المتصفح.
- لا تعتمد على جهاز المستخدم أو بقاء صفحة الموقع مفتوحة.
- أضف Health Checks ومراقبة اتصال Telegram وإعادة الاتصال تلقائياً.
- استخدم آلية إعادة تشغيل تلقائية عند تعطل العامل.
- قدم ملفات Docker وDocker Compose عند ملاءمتها.
- وفر ملف إعداد بيئة نموذجي .env.example دون أسرار حقيقية.
- اكتب تعليمات نشر عملية على استضافة تدعم العمليات الخلفية المستمرة وقاعدة البيانات والمهام الدائمة.
- إذا استخدمت Replit، تحقق من أن نوع الاستضافة المختار يسمح بتشغيل العامل باستمرار، ووضح أي اشتراك أو إعداد مطلوب بدلاً من الادعاء أن التشغيل المجاني دائم.
- اجعل سجلات الخدمة قابلة للمراجعة، ووضح خطوات تحديث المشروع والنسخ الاحتياطي والاستعادة.
- أضف زر إيقاف مؤقت يحافظ على إعدادات المستخدم ولا يحذف بياناته.

15. شروط التسليم:
- أنشئ المشروع فعلياً بملفات المصدر الكاملة، وليس مجرد شرح أو مخطط.
- اربط الواجهة الأمامية بالـ Backend وقاعدة البيانات فعلياً.
- لا تستخدم أزراراً شكلية أو بيانات ثابتة بدلاً من الوظائف المطلوبة.
- نفذ عمليات الإضافة والتعديل والحذف والتفعيل والتعطيل بشكل حقيقي.
- أضف اختبارات للترجمة والتوجيه ومنع التكرار ومعالجة الأخطاء.
- تحقق من صلاحية API وأسعار السوق، ولا تعرض نجاحاً وهمياً.
- اكتب README باللغة العربية يشرح التثبيت والإعداد والتشغيل والنشر والصيانة.
- ابدأ أولاً بمراجعة المتطلبات ووضع هيكل المشروع، ثم نفذ التطبيق كاملاً.
- إذا تعذر تنفيذ أي ميزة بسبب قيود Telegram أو مزود خارجي، اذكر السبب بدقة ونفذ أفضل بديل قانوني وعملي.
- لا تتوقف عند إنشاء الواجهة؛ أكمل التكامل الخلفي واختبر دورة العمل من استقبال الرسالة حتى نشرها.
- في النهاية، أعطني تقريراً يوضح الملفات المنفذة، والخدمات المطلوبة، والمتغيرات التي يجب ضبطها، ونتائج الاختبارات، وخطوات نشر الموقع وتشغيله 24/7.
