# MZ Telegram Bots

منصة عربية RTL لمالك واحد لإدارة استقبال رسائل قنوات Telegram العامة وإعادة نشرها في قنواته، مع إعدادات مستقلة للترجمة والمصدر والأسعار. لا توجد حسابات عامة أو تسجيل بالبريد الإلكتروني.

## حالة التسليم والتحقق

- الواجهة والخادم وقاعدة PostgreSQL موصولة فعلياً، ولا توجد قنوات أو رسائل أو أسعار تجريبية.
- إدارة المصادر والوجهات: إضافة، تعديل، حذف بتأكيد، تفعيل وتعطيل، اختبار الوصول أو صلاحية النشر، إعدادات مستقلة.
- قواعد ربط متعددة المصادر والوجهات، معاينة لا ترسل، سجل تسليم قابل للبحث والتصفية، إعادة محاولة للفاشل والمعلق، وسجل أحداث.
- جلسة المالك آمنة، وكلمة المرور مخزنة بـ Argon2id، وتغييرها يبطل الجلسات الأخرى. إعداد كلمة المرور الأولية يُستخدم مرة واحدة فقط.
- جلسة MTProto مخزنة مشفرة بـ AES-256-GCM، ولا تُعاد إلى المتصفح أو السجلات.
- طابور دائم في PostgreSQL، تسجيل لكل محاولة، إعادة محاولة متدرجة، وقيود فريدة لمنع التكرار. لا يحتاج Redis في هذا الإصدار.
- نجحت 21 حالة اختبار آلي بعد إضافة تدفق التحقق بخطوتين، مع فحص الأنواع في المشروع. بيانات الاختبارات تُنفذ داخل معاملة تُلغى بالكامل؛ لا تبقى قنوات اختبار.
- تم التحقق من صفحة الدخول على الكمبيوتر والهاتف، ومن رفض API الإداري للطلبات غير المسجلة برمز 401. **الواجهة بعد تسجيل الدخول لم تُتحقق بصرياً**؛ لا توجد آلية تجاوز دخول للاختبارات.
- تحقق جلب سعري السوق فعلياً. اختبار Bot API أعاد `Not Found` ببيانات البوت المضافة وقت البناء؛ راجع `BOT_TOKEN` في الأسرار. لا يظهر نجاح وهمي.
- **لم تُختبر دورة استقبال رسالة ونشرها على قنواتك الحقيقية**؛ لم تُضف بعد قنواتك ولم تُفوّض جلسة القراءة. اختبارات الشفرة لا تعني نجاح النشر الخارجي.

## الأسرار المطلوبة

أدخل القيم في **Replit Secrets**، ولا ترسلها بالمحادثة أو تكتبها في المستودع:

| المتغير | الاستخدام |
|---|---|
| `ADMIN_INITIAL_PASSWORD` | كلمة مرور دخول المالك عند أول تشغيل؛ يُنصح بطول 12 حرفاً على الأقل |
| `SESSION_SECRET` | قيمة عشوائية من 32 حرفاً على الأقل لتشفير جلسة Telegram؛ لا تغيّرها دون إعادة تفويض الجلسة |
| `BOT_TOKEN` | من BotFather؛ يجب أن ينجح اختبار `getMe` |
| `API_ID` و`API_HASH` | من `my.telegram.org` لتطبيق MTProto |
| `DATABASE_URL` | يُدار بواسطة PostgreSQL في Replit؛ الاستضافة الخارجية توفر اتصالها الخاص |
| `AI_INTEGRATIONS_OPENAI_BASE_URL` و`AI_INTEGRATIONS_OPENAI_API_KEY` | يُعدّهما Replit AI Integrations تلقائياً |
| `DEEPL_API_KEY` | اختياري، فقط عند اختيار DeepL Free API |

بعد الإعداد الأولي، غيّر كلمة المرور من صفحة الإعدادات. تغيير `ADMIN_INITIAL_PASSWORD` وحده لا يستبدل كلمة المرور المحفوظة. الجلسات تنتهي بعد 8 ساعات، وCookies من نوع HttpOnly وSameSite=Lax وSecure عبر HTTPS. يوجد حد 8 محاولات دخول لكل 15 دقيقة لكل عنوان و300 طلب إداري لكل دقيقة.

## بدء الاستخدام

1. ادخل بكلمة المرور التي أضفتها إلى الأسرار.
2. افتح **الخدمات وتيليجرام** واضغط **اختبار البوت**. إذا ظهر `Not Found` أو `Unauthorized` راجع الرمز في BotFather وحدّث `BOT_TOKEN` بأمان ثم أعد تشغيل الخادم.
3. ابدأ تفويض QR من الصفحة نفسها. من تطبيق Telegram الرسمي: الإعدادات ← الأجهزة ← ربط جهاز، ثم امسح الرمز. تعامل مع QR كبيان دخول حساس، ولا تشاركه أو تلتقط له صورة عامة.
4. إذا طلب Telegram التحقق بخطوتين بعد المسح، يظهر حقل مخصص داخل لوحة المالك. أدخل كلمة المرور فيه مرة واحدة؛ تُمرر للمكتبة عبر API محمي، لا تُحفظ أو تُسجّل، وتمسح الواجهة القيمة بعد الإرسال. بعد نجاح المصادقة فقط تحفظ الجلسة المشفرة. توجد حماية بعدد محدود من المحاولات.
5. أضف المصادر العامة التي تملك حق إعادة نشرها واختبر الوصول لكل مصدر. أضف الوجهات وأضف البوت **مشرفاً مع صلاحية نشر الرسائل**، ثم اختبر الصلاحية. إرسال رسالة اختبار يحتاج تأكيداً.
6. أنشئ قواعد الربط. اضبط الترجمة ورابط المصدر لكل مصدر، وشريط الأسعار لكل وجهة.
7. اختبر شكل النص في صفحة المعاينة. المعاينة قد تستدعي خدمة ترجمة مدفوعة لكنها **لا تنشر**.
8. شغّل العامل. لن يعرض التشغيل كناجح قبل نجاح اتصال البوت وجلسة القراءة.
9. أرسل رسالة جديدة إلى مصدر تستطيع التحكم فيه، ثم تابع سجل التسليم وTelegram نفسه لتأكيد الدورة الحقيقية.

**قيد Telegram:** Bot API لا يتيح قراءة جميع القنوات العامة تلقائياً. القراءة هنا عبر حساب مفوّض MTProto له صلاحية القراءة. الروابط الخاصة والمجموعات والحسابات الشخصية ليست مصادر مدعومة بهذا الإصدار. المحتوى المحمي من إعادة التوجيه يُتجاهل؛ لا نتجاوز الحماية. التزم بشروط Telegram وحقوق أصحاب المحتوى.

## التفويض المحلي البديل

في طرفية خاصة بالمالك، مع الأسرار مضبوطة وقاعدة البيانات المستهدفة صحيحة:

```bash
pnpm --filter @workspace/api-server run authorize-telegram
```

هذا مسار بديل إذا تعذر إكمال المصادقة من لوحة المالك. الأداة تسأل محلياً عن الهاتف ورمز الدخول وكلمة مرور التحقق بخطوتين مع إخفاء المدخلات. لا تحفظ كلمة المرور ولا تطبع جلسة Telegram. تحفظ **الجلسة المشفرة فقط** في قاعدة البيانات. لا تُشغّل هذا الأمر عبر endpoint، ولا ترسل المدخلات أو المخرجات إلى المحادثة. أعد تشغيل الخدمة بعد نجاحه، أو انتظر دورة إعادة الاتصال.

في تدفق اللوحة، خطوة كلمة المرور متاحة بعد مسح QR فقط، خلف جلسة المالك وفحص Origin/CSRF وحدّ خمس محاولات لكل 15 دقيقة لكل عنوان. كلمة المرور تعبر HTTPS في جسم الطلب ولا تدخل URL أو سجلات Pino/التدقيق. تُمرر إلى مكتبة MTProto للتحقق بـSRP في الذاكرة فقط، ولا تُكتب إلى PostgreSQL أو تخزين المتصفح. تُحفظ الجلسة المشفرة وحدها بعد تأكيد Telegram نجاح المصادقة.

## سلوك الاستقبال والإرسال ومنع التكرار

- عند تفعيل مصدر جديد لأول مرة يبدأ من أحدث رسالة؛ لا يعيد نشر أرشيفه التاريخي.
- يوجد استقبال أحداث مستمر بعد الانضمام للقناة، واستدراك دوري للفجوات كل دقيقة حتى لو كان المتصفح مغلقاً.
- المؤشر الدائم يتقدم بترتيب معرّفات الرسائل في الاستدراك، لا بترتيب وصول أحداث قد يصل بعضها متأخراً.
- PostgreSQL يمنع تكرار `(المصدر، معرّف الرسالة)` و`(الرسالة، الوجهة)`. قفل قيادة PostgreSQL يسمح بعامل معالجة قائد واحد؛ العمليات الأخرى احتياطية.
- الصور تُنزّل إلى الذاكرة وقت الإرسال فقط؛ لا تُحفظ صور أو جلسات خام في المستودع أو قاعدة البيانات.
- النصوص الطويلة تُقسم ضمن حدود Telegram. للصورة تعليق إذا أمكن، وإلا تُرسل الصورة ثم النص. تُحفظ معرّفات الأجزاء المنشورة قبل الانتقال للجزء التالي.
- لا تُرسل رسالة من مصدر معطل أو إلى وجهة معطلة أو بعد حذف قاعدة ربطها. تعطيل القناة يحفظ إعداداتها؛ حذفها يحذف الربط ويبقي سجل الرسائل.
- الإيقاف المؤقت يمنع المحاولات التالية، لكن طلب إرسال جارٍ بالفعل قد يكتمل.
- الأخطاء المؤقتة تعاد بتأخير متصاعد، و`retry_after` وFloodWait يُحترمان. أخطاء الصلاحيات تُسجل بدلاً من إعادة المحاولة بلا نهاية.
- **لا يمكن ضمان exactly-once عبر Bot API عند انقطاع الشبكة بعد قبول الرسالة**؛ ليس فيه مفتاح idempotency للإرسال. لذلك تُسجل الحالات الملتبسة `unknown` ولا تُعاد تلقائياً أو بزر إعادة المحاولة. راجع القناة والسجل يدوياً. الأولوية لمنع التكرار، ولو تطلب ذلك تدخلاً يدوياً.
- الرسائل الفاشلة والمعلقة تعاد يدوياً بعد تصحيح السبب. إعادة المحاولة تستخدم خطة المنشور الأصلية، ولا تُعدّل أسعار الرسالة في كل محاولة.
- التعديل والحذف اللاحق للمنشور الأصلي، ألبومات الوسائط والفيديو والملفات، ونشر تحديث أسعار مستقل أو تحديث منشورات قديمة ليست مدعومة في هذا الإصدار.
- مرشح «التوصيات فقط» يعتمد كلمات مالية عربية وإنجليزية، وليس تصنيفاً مالياً مضموناً. راجع المعاينة.

## الترجمة

مزود الترجمة معطل افتراضياً. من صفحة الترجمة اختر Replit AI أو DeepL، ثم فعّل «ترجمة الرسائل إلى العربية» للمصادر المطلوبة فقط.

Replit AI Integrations يستخدم OpenAI، ولا يحتاج مفتاحاً منك، ويستهلك من أرصدتك. النموذج الافتراضي `gpt-5-mini`. DeepL في هذا الإصدار يستخدم عنوان Free API؛ يحتاج مفتاحاً مناسباً وقد تختلف تغطية اللغات وحدود الاشتراك.

الأرقام والرموز المالية والروابط والمعرفات تُحمى بعلامات مؤقتة، وترفض النتيجة إذا اختفت العلامات أو تكررت. عند الفشل يطبق خيار المصدر: نشر الأصل مع تسجيل حالة fallback، أو تعليق الرسالة. لا تتأثر المصادر الأخرى.

التنسيقات الأصلية المدعومة تُحفظ قدر الإمكان عند اختيار HTML؛ لا يُقبل HTML خام من محتوى الرسالة. الترجمة قد تفقد تنسيق مواضع الكلمات، والنص الطويل يُرسل بتنسيق نصي آمن. الروابط النصية الأصلية تحفظ عند استخدام HTML.

## السوق وشريط المنشورات

- البيتكوين: [Coinbase Spot Price API](https://docs.cdp.coinbase.com/coinbase-app/track-apis/prices)، المسار `https://api.coinbase.com/v2/prices/BTC-USD/spot`.
- الذهب الفوري: [Gold API](https://gold-api.com/)، المسار `https://api.gold-api.com/price/XAU`.
- تحديث افتراضي كل 300 ثانية، وحد أدنى 60 ثانية لتجنب إساءة استخدام حدود المزود.
- الاتجاه ▲/▼ أو المحايد مبني على **آخر قراءة ناجحة**، والسعر السابق محفوظ في PostgreSQL.
- يظهر المصدر ووقت آخر جلب ناجح، وتُرفض استجابة مزود غير صالحة. البيانات القديمة تحمل تحذيراً أو تُخفى حسب الوجهة.
- إعدادات الوجهة مستقلة: تشغيل الشريط، الذهب، البيتكوين، الترتيب، سياسة السعر القديم، والتنسيق.
- الشريط يضاف أعلى **المنشور الجديد**، لا في رسالة أسعار منفصلة، ولا يغير منشورات سابقة.
- لون السهم في واجهة الإدارة أخضر/أحمر؛ Telegram لا يدعم تلوين نص تعسفي في الرسائل، لذا يُنشر السهم كنص، دون ادعاء لون لا يدعمه Telegram.
- قد تختلف الأسعار عن منصات التداول، أو يتوقف مزود خارجي؛ ليست تغذية تنفيذ أو توصية استثمارية.

## التطوير والاختبارات

المتطلبات: Node.js 24 وpnpm 10 وPostgreSQL.

```bash
pnpm install --frozen-lockfile
pnpm --filter @workspace/api-spec run codegen
pnpm --filter @workspace/db run push   # تطوير فقط
pnpm run typecheck
pnpm --filter @workspace/api-server run test
```

شغّل خدمات التطوير من Workflows المهيأة في Replit. إعداد PORT وBASE_PATH يأتي من كل خدمة. لا تبدأ خادمين لنفس الخدمة ولا تنسخ أسراراً إلى الشفرة.

لتطوير مخطط جديد عدّل Drizzle، وطبّقه على قاعدة التطوير، ثم ولّد SQL مرجعياً بـ:

```bash
pnpm --filter @workspace/db exec drizzle-kit generate --config drizzle.config.ts
```

**قاعدة إنتاج Replit المدارة:** النشر يقارن مخطط التطوير والإنتاج ويطبق التغييرات بعد مراجعة المستخدم؛ لا تشغّل SQL ترحيل مخصصاً عند بدء التطبيق أو في production build. ملف SQL المرفق مرجع قابل للمراجعة، لا مشغّل ترحيل إضافياً.

## النشر والتشغيل 24/7

1. استخدم Publish واختر **Reserved VM** مناسباً لعملية خلفية دائمة، مع قاعدة إنتاج PostgreSQL. Autoscale قد يتوقف دون طلبات وليس الخيار المناسب لهذا العامل.
2. راجع موارد الخادم والتكلفة في واجهة Replit؛ لا يوجد وعد بتشغيل مجاني دائم.
3. تأكد من توفر الأسرار اللازمة في بيئة الإنتاج. البيانات والجلسة في قاعدة التطوير لا تعني أنها موجودة في قاعدة الإنتاج؛ فوّض جلسة Telegram على البيئة التي ستعمل فعلياً.
4. لا تترك نفس حساب القراءة منشطاً للنسخ والنشر من التطوير والإنتاج معاً؛ أوقف عامل التطوير عند التحويل للإنتاج لتجنب نشر مزدوج عبر قاعدتين مستقلتين.
5. الخدمات المهيأة تبني واجهة Vite وتخدم ملفاتها الثابتة، وتبني API ثم تشغل `artifacts/api-server/dist/index.mjs`.
6. API يستمع إلى PORT؛ مساراته تحت `/api`. فحص الصحة `/api/healthz` يفحص PostgreSQL ويعيد 503 عند الفشل.
7. حالة العامل وسجلاته من صفحة الخدمات؛ وسجلات العملية من Monitoring/Logs في Replit. فعّل التنبيه والمراقبة المناسبين في استضافتك. عند تعطل العملية يجب أن يعيد مشرف الاستضافة تشغيلها؛ يعيد العامل تحميل حالته من PostgreSQL.

خارج Replit استخدم استضافة تسمح بعملية Node دائمة ومشرف عمليات مثل systemd، وHTTPS reverse proxy يوجه `/api` للخادم وبقية الطلبات للواجهة مع SPA fallback. خزّن الأسرار في مدير أسرار، وخصص PORT وBASE_PATH للبناء. لا حاجة إلى Docker في بيئة Replit، ولم تُضف ملفات حاويات غير قابلة للتشغيل فيها.

## النسخ الاحتياطي والاستعادة والصيانة

- استخدم خيارات النسخ الاحتياطي وPoint-in-time restore المتاحة في أداة Database في Replit حسب إعداد المشروع.
- للتصدير اليدوي من البيئة الصحيحة، يلزم `pg_dump` من أدوات عميل PostgreSQL:


السكربت لا يغيّر القاعدة. يضع النسخة بصلاحيات خاصة في `generated-artifacts/backups/`، وهي مستثناة من Git والنشر. انقلها فوراً إلى تخزين دائم خاص مشفر؛ مجلد المشروع ليس استراتيجية نسخ احتياطي. لا تشارك النسخة لأنها تحتوي بيانات القنوات وهاش كلمة المرور وجلسة Telegram المشفرة. احفظ `SESSION_SECRET` في مدير أسرار مستقل لتتمكن من فك الجلسة بعد الاستعادة.

للاستعادة: أوقف العامل أولاً، خذ نسخة من الوضع الحالي، واستعد إلى **قاعدة اختبار جديدة** أولاً باستخدام `pg_restore --no-owner --no-acl` للتحقق، ثم استخدم آلية استعادة قاعدة الإنتاج المناسبة لاستضافتك بعد مراجعة أثر الاستبدال. لا تنفذ استعادة فوق قاعدة حية دون موافقة ونسخة احتياطية. استعادة قاعدة Replit لا تعيد نسخة الشفرة تلقائياً؛ طابقهما قبل تشغيل العامل.

قبل التحديث: نسخة احتياطية، إيقاف مؤقت، مراجعة المخطط، فحص الأنواع والاختبارات، نشر، ثم مراجعة الخدمات وإعادة تشغيل العامل. لا تغيّر SESSION_SECRET دون خطة لإعادة تفويض Telegram. راجع السجلات دورياً، ودوّر BOT_TOKEN عند الاشتباه بتسربه.
